# S08 D1/D3-DEV-07 — Stripe evidence contracts and field mapping (development record)

Status: DEVELOPMENT ONLY, INERT. Financial activation: NO-GO. Stacked on DEV-06 (PR #226, unmerged when written). No migration, no provider call, synthetic fixtures only. Code: `apps/api/src/billing/stripe-read/`.

## What was added
- **Versioned contract** (`EVIDENCE_CONTRACT_VERSION = S08-STRIPE-EVIDENCE/1`): every fact is VERIFIED, CONFIRMED_ABSENT, UNRESOLVED or CONTRADICTORY with origin and mapping; the bundle also carries `schemaDrift` and a computed `complete`.
- **Provider profiles** (`provider-profiles.ts`): a mapping exists only for an exact registered API version (`2026-05-27.dahlia`). Proof level `SDK_SCHEMA_UNPROVEN_LIVE`: shapes come from the SDK type definitions in the lockfile (stripe@22.3.2, API 2026-06-24.dahlia), which show a field exists, not how Stripe behaves. Any other version maps nothing.
- **Pagination** (`pagination.ts`): a list is complete only if the recorded page sequence provably covers it (cursor chain, final `has_more=false`, nothing after, unique ids, page/item limits). Incomplete is never "absent".
- **Lines** (`line-normalizer.ts`): invoice, id, currency, livemode and total checks; subscription lines = base/proration; invoice-item lines stay unattributed unless SEPARATE idempotency evidence proves the parent item's key (not obtainable from Stripe objects), then they must match exactly one frozen allocation by key and amount (read-only). Fabricated, mislabelled, mis-sized or duplicate benefit lines are contradictions; a metadata label is preserved and never trusted.
- **Payment** (`payment-normalizer.ts`): settlement needs exactly one `paid` invoice payment of this invoice, same currency, amount equal to the invoice's paid amount, a coherent paid time, and an unambiguous payment intent/charge. A "paid" label alone is not settlement; duplicates, several payments and other-invoice payments fail closed.
- **Refunds and disputes** (`refund-dispute-normalizer.ts`): association to the settling payment by payment intent/charge; literal status mapping (inquiry states and `prevented` stay `unknown`); confirmed absence only from a complete empty read; bounded totals; overlap between a refund and a dispute is always undetermined (the provider does not say) and several disputes are undefined, both preserved as contradictions. No recovery logic.
- **Bridge**: any bundle contradiction or drift turns refund/dispute into `unknown`; the D3 evidence is judged on the history's own completeness so the D3 classifier itself reports contradictions. Only sealed `MOCK_FIXTURE` evidence converts; real evidence still reaches the classifiers as an unaccepted kind (UNRESOLVED / EVIDENCE_KIND_UNSUPPORTED).
- **Test adapters** (`extended-source.ts`): `ExtendedReadSource` is typed and checked as `MOCK_FIXTURE`; there is no real implementation and the real transport still has exactly two paths. The four reads remain NOT_AUTHORIZED in the registry (their contract strings now name the normalizers).
- Real adapter: refuses an API version with no profile.
